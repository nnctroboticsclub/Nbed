# 最適化と F303K8 対応の検証（2026-10-23）

## 変更点

- GPIO は初期化時にポートとピンマスクを保持し、読み書きのたびのピン検証・変換を省略。
  保持用に各オブジェクトの RAM 使用量は増えます。
- ADC は直前の入力チャンネルを保持し、同じ入力の連続読取りでは HAL のチャンネル再設定を省略。
  別の入力へ切り替える場合は再設定します。
- `printf` の出力は newlib から受け取ったバッファをまとめて UART へ渡します。
  HAL の長さ上限 65535 byte を超える場合だけ分割し、送信失敗を呼出し元へ返します。
- `System::Initialize()` の重複した初期化手順を一本化。
- PWM の周期・デューティ計算を F3/F4 で共通化。32 bit TIM2 の比較値が符号付き
  32 bit 整数の範囲を超える場合に、`lround()` で値が壊れる問題を修正。
- 時刻の読取りを一貫したサンプルに揃え、HAL の 32 bit ミリ秒カウンタの周回を
  追跡。`Time::Microseconds()` と `Timer` は約49.7日で時刻が巻き戻らなくなります。
  `Time::Milliseconds()` は HAL と同じ 32 bit のままです。
- 整数版 `Sleep()` も chrono 版の分割待機を使い、`UINT32_MAX` の待機が HAL 内で
  オーバーフローする問題を回避。
- 不正な周辺機能番号・割り込み優先度、1 Mbps を超える CAN 速度、HAL と一致しない
  HSE 周波数を拒否。初期化前のエンコーダ角度取得は 0 度を返します。
- F303K8 用の実装、HAL 設定、ビルド環境、サンプル、ピン表を追加。
  MCU ごとに実装とリンカスクリプトを選び、F3 には `-Os`、F4 には従来の `-O3` を適用。

既存の F4 公開 API は維持しています。DMA の一括初期化を含む F4 の起動手順も維持しています。
処理時間の実機測定は行っていません。

## 確認結果

| 確認 | 結果 |
| --- | --- |
| F4 の既存8環境 | 全てビルド成功 |
| `f3-blink` / `f3-all-test` | 両方ビルド成功 |
| 別の利用プロジェクト（F3/F4） | 両方ビルド成功。グローバル別名・待機関数・既定コンソールを無効化した構成も確認 |
| Python / ホスト C++ 回帰テスト | 26件成功。既存の任意実行の PlatformIO 統合テスト8件はスキップ |
| コンパイルDB | F3/F4 の各ソースに正しい MCU マクロが残ることを確認 |
| C++ 整形 | clang-format 23.1.1 で変更ファイルを整形 |
| 実機書込み・波形・外部通信 | 未実施 |

| ビルド | Flash | 通常 RAM |
| --- | ---: | ---: |
| F4 LED（変更前） | 26412 byte | 1688 byte |
| F4 LED（変更後） | 26308 byte | 1696 byte |
| F3 LED | 23084 byte / 64 KB | 1056 byte / 12 KB |
| F3 全機能 | 37304 byte / 64 KB | 1336 byte / 12 KB |

サイズは PlatformIO の表示値で、ヒープ・スタックの実行時ピーク使用量は含みません。
F3 には別領域の 4 KB CCMRAM もありますが、この RAM 使用率には含めていません。

